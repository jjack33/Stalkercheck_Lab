# Project Instructions & Conventions

## File Preservation & Version Annotation Policy
- **Non-Destructive Updates**: When modifying, refactoring, or updating existing components, avoid unannounced removal or deletion of previous files and architectures.
- **Inline Version Annotations**: Clearly annotate updated sections and components with version markers, changelog comments, and historical notes so previous behavior and structures can be referenced or restored easily.
- **Clean Fallbacks**: Ensure legacy color themes, mock definitions, and verification models remain accessible or documented in source comments for auditability and rollback capability.
